# 코덱스(Codex) 기반 자동화 재설계 — 발주서

> **이 문서의 용도**: ChatGPT(또는 Codex 자신)에게 그대로 주고 구현을 시키는 발주서다.
> 디스코드/헤르메스 없이, **저장소와 워크트리가 곧 사무실**이 되는 설계.

---

## 0. 먼저 — 세 가지 방식의 정직한 비교

"뭐가 더 이질적이지 않은가"에 대한 답부터.

| | ① 직접 API (현재 구현) | ② Codex CLI (이 문서) | ③ 헤르메스+디스코드 |
|---|---|---|---|
| 엔진 | OpenAI API 를 코드가 직접 호출 | `codex exec` 를 코드가 호출 | ①이나 ② 위에 UI만 얹음 |
| **요금** | **종량제** (쓴 만큼 청구, 상한 없음) | **ChatGPT 구독에 포함** (Plus/Pro 한도 내 고정) | 엔진 따라감 |
| 준비물 | API 키 발급 + 결제 등록 | `codex login` (ChatGPT 계정 로그인) | 봇 등록 + 서버 세팅 |
| 병렬 작업 | 코드로 직접 구현해야 함 | **git 워크트리로 자연스럽게** | — |
| 사람 개입 방식 | 터미널 로그 | **git diff / PR 리뷰** | 디스코드 버튼 |
| 통제 장치(게이트·캐논·정체감지) | 전부 유지 | **전부 유지** (오케스트레이터가 우리 것) | 유지 |
| 추가 구현량 | 0 (완성됨) | **작음** (프로바이더 1개 추가) | 큼 (봇 전체) |
| 이질감 | 가장 적음 | 적음 — 파일 기반 설계와 찰떡 | UI가 하나 더 늘어남 |

### 결론 (추천)

1. **②를 채택한다.** 결정적 이유는 두 가지다:
   - **요금**: 이미 ChatGPT 구독이 있다면 API 종량제 대신 구독 한도로 돌릴 수 있다.
     소설 1편에 50회 호출인 시스템에서 이 차이는 크다.
   - **워크트리 병렬**: 사용자의 직감이 맞다. 아웃라인 확정 후 회차별 집필은 서로
     독립적이므로, 워크트리 N개에서 동시에 쓰면 벽시계 시간이 회차 수만큼 줄어든다.
2. **디스코드는 접는다** (당분간). 결재·관찰은 git diff 와 터미널 보고로 충분하다.
   코덱스 방식에서는 "채널"이 아니라 "브랜치"가 대화 장소다.
3. ①은 삭제하지 않는다. 프로바이더 하나를 추가하는 것이므로 `--provider openai` 와
   `--provider codex` 를 언제든 갈아탈 수 있다. **기존 통제 계층은 한 줄도 버리지 않는다.**

> **정직한 주의 1**: Codex 는 코딩 에이전트다. 소설을 "파일에 쓰는 작업"으로 시키면 잘 하지만,
> 단순 텍스트 생성 대비 실행 오버헤드(세션 기동)가 있다. 회당 몇 초의 추가 비용.
> **정직한 주의 2**: 구독 한도(주간 사용량)에 걸리면 멈춘다. 체크포인트/재개가 있으므로
> 치명적이지 않지만, 대량 생산 시에는 결국 API 종량제(①)가 필요할 수 있다.
> **정직한 주의 3**: 아래 CLI 플래그는 버전에 따라 다를 수 있다.
> **`codex-cli 0.145.0` 에서 검증 완료된 사항** (2026-07 확인):
> - 읽기 전용 실행: `codex exec --sandbox read-only`
> - 최종 응답만 안전하게 받기: `--output-last-message <파일>`
> - JSONL 이벤트 수집: `--json`
> - 모델 지정: `--model`
> - 프롬프트 stdin 전달 가능
> 다른 버전이면 `codex exec --help` 로 재확인.

## 1. 전체 그림

```
사용자: node src/cli.js run --idea "..." --provider codex
  │
  ▼
┌────────────────────── 소설 공장 (기존 그대로) ──────────────────────┐
│  스튜디오 팀장 → 기능 팀장 → 팀원 릴레이                              │
│  버스(events.jsonl) · 게이트 · 캐논 주입 · 개고 루프 · 퇴고 · 정산     │
│                                                                    │
│  달라지는 곳은 단 하나, LLM 호출부:                                   │
│      기존:  fetch(api.openai.com)                                   │
│      신규:  spawn("codex", ["exec", ...])   ← ChatGPT 구독으로 실행   │
└────────────────────────────────────────────────────────────────────┘
  │
  ▼ (2단계) 회차 집필만 워크트리로 병렬화
wt/ch01  wt/ch02  wt/ch03   ← 각각 독립 codex 세션이 집필
  └────────┴────────┘
       머지 → 품질 루프(순차) → 퇴고 → 납품
```

**핵심 원칙**: 코덱스는 **팀원의 손**을 대체할 뿐이다. 조직(누가 뭘 하고 누가 검사하는가)은
그대로 우리 오케스트레이터가 쥔다. 이유: 코덱스에게 조직까지 맡기면 "알아서 잘"의 세계로
돌아간다 — 게이트도, 정체 감지도, 캐논 주입도 사라진다. 그건 이 프로젝트가 해결한 문제다.

## 2. 1단계 — `codex` 프로바이더 추가 (최소 변경, 최대 효과)

### 2-1. 무엇을 만드나

`src/llm.js` 의 `_dispatch()` 에 케이스 하나를 추가한다:

```js
case 'codex': return this._codex(req);
```

`_codex(req)` 의 계약:

1. `spawn('codex', args, {...})` 로 **비대화(non-interactive) 실행**을 한다.
   - 프롬프트는 **stdin 또는 인자**로 전달 (셸 문자열 결합 금지 — 인자 배열만)
   - 시스템 프롬프트 + 유저 프롬프트는 하나의 프롬프트로 합쳐 전달한다
     (역할 구분은 텍스트 안에 `### 시스템 규칙` / `### 작업` 헤더로)
2. **읽기 전용 샌드박스**로 실행한다. 1단계에서 코덱스는 파일을 만들지 않는다 —
   **표준 출력으로 결과만 뱉는다.** 파일 저장은 기존대로 우리 가드(guard.js)가 한다.
   (코덱스에게 쓰기를 주면 우리 백업·마스킹·경로검증을 우회하게 된다)
3. 응답 추출은 **`--output-last-message <임시파일>` 을 1순위**로 쓴다 (0.145.0 검증됨).
   임시파일은 워크스페이스 `.cache/` 아래에 만들고, 읽은 뒤 즉시 삭제한다.
   stdout 로그 파싱은 폴백으로만 두고, 진행 로그를 응답으로 착각하지 않게 한다.
   전체 호출 형태 (검증된 플래그 기준):
   ```
   codex exec --sandbox read-only --output-last-message <tmp> [--model <m>]   (프롬프트는 stdin)
   ```
4. 타임아웃(기존 `timeoutMs` 설정 재사용) 초과 시 프로세스를 kill 하고 재시도 루프에 맡긴다.
5. 종료 코드 ≠ 0 이거나 응답이 비면 예외 → 기존 백오프 재시도(2s/4s/8s/16s)가 그대로 동작.

### 2-2. config 추가

```json
"codex": {
  "bin": "codex",
  "model": "",              // 비우면 codex 기본값. 지정 시 --model 로 전달
  "extraArgs": [],           // 버전별 플래그 차이 흡수용
  "mergeSystemIntoPrompt": true
}
```

`apiKeyEnv` 없음 — 인증은 사전에 사용자가 `codex login` 으로 마친다.
`doctor` 명령에 코덱스 점검 추가: `codex` 실행 파일 존재 + 로그인 상태 확인.

**Windows 주의 (중요)**: npm 전역 설치된 코덱스는 Windows 에서 `codex.cmd` 다.
최신 Node 는 보안상(CVE-2024-27980) `.cmd` 를 `shell:false` 로 spawn 하면 EINVAL 로 거부한다.
해법: **프롬프트를 stdin 으로만 전달**하면 argv 에는 우리가 통제하는 고정 플래그와
경로만 남으므로, Windows 에 한해 `shell:true` 를 써도 인젝션 표면이 없다.
- 탐색 순서: `providers.codex.bin` 설정값 → `codex` → (win32) `codex.cmd`
- **사용자 텍스트를 argv 에 절대 싣지 않는다** — 이 규칙이 shell:true 를 안전하게 만든다
- macOS/리눅스는 `shell:false` 유지

### 2-3. 지켜야 할 것 (기존 계약)

- `completeStructured()` 의 JSON 강제·자가교정 루프는 **그대로 codex 응답에도 적용**된다.
  프로바이더가 바뀌어도 출력 계약은 바뀌지 않는다.
- 예산 카운터(호출 수·토큰 추정)도 그대로 적립한다. 구독이라도 한도는 있다.
- 온도 개념이 없거나 무시될 수 있다 — 무시되면 그냥 둔다 (치명적이지 않음).

### 2-4. 완료 기준 (DoD)

```bash
codex login                                   # 사전 1회
node src/cli.js doctor                        # codex: ✔ 로그인됨
node src/cli.js run --idea "테스트" --chapters 1 --provider codex
```
- 1회차가 끝까지 나오고, 게이트 반려·재시도가 로그에 정상 동작
- `reports/run-summary.json` 의 usage.calls 가 정상 집계
- API 키 환경변수가 **하나도 없는 상태**에서 성공해야 한다 (구독 인증만으로)

## 3. 2단계 — 워크트리 병렬 집필

### 3-1. 왜 회차 집필만 병렬인가

| 구간 | 병렬 가능? | 이유 |
|---|---|---|
| 리서치→세계관→인물→시놉→문체→아웃라인 | ✘ 순차 | 각 단계가 앞 단계 산출물을 먹는다 |
| **회차별 초고 (WRITER_1)** | **✔ 병렬** | 아웃라인·캐논만 있으면 서로 독립 |
| 검토→비평→개고 루프 | ✘ 순차 권장 | 품질 판정이 캐논을 갱신하므로 순서 필요 |
| 연속성 점검 | ✘ 반드시 순차 | 1화 확정 사실이 2화 점검의 입력이다 |
| 전면 퇴고·납품 | ✘ 순차 | 전체를 한 덩어리로 봐야 한다 |

즉 "다 병렬"이 아니라 **초고 팬아웃(fan-out) → 품질 순차(fan-in)** 구조다.
초고가 전체 시간의 절반 이상을 먹으므로 이것만으로 벽시계 시간이 크게 준다.

### 3-2. 워크트리 규약

```bash
# 오케스트레이터가 수행 (사용자는 모른다)
git worktree add .wt/ch01 -b draft/ch01
git worktree add .wt/ch02 -b draft/ch02
...
```

- 각 워크트리에서 `codex exec` 를 **쓰기 허용 샌드박스**(해당 워크트리 한정)로 실행
- 코덱스에게 주는 과제: "아웃라인 N화 + 캐논 요약을 읽고 `chapters/chNN.draft1.md` 를 작성하라"
- 회차 파일은 서로 다른 파일이므로 **머지 충돌이 구조적으로 없다**
- 완료 후: 각 브랜치를 메인 작업 브랜치로 머지 → 워크트리 제거 → 품질 루프는 기존 순차 파이프라인
- 실패한 회차는 해당 워크트리만 재실행 (다른 회차에 영향 없음)

### 3-3. AGENTS.md — 공통 규칙의 새 집

코덱스는 저장소의 `AGENTS.md` 를 자동으로 읽는다. 우리의 `prompts/common.md`(조직 규칙·
핸드오프 계약·안전 규칙)를 **AGENTS.md 로 변환해 워크트리 루트에 배치**한다.

- 내용: common.md 의 안전 규칙 + "본문 파일만 작성, 다른 파일 수정 금지" +
  "완료 시 bus/ 에 HANDOFF_EVENT JSON 파일을 남겨라" (파일명: `outbox/<역할>-<회차>.json`)
- 역할별 프롬프트(writer1.md 등)는 과제 텍스트에 포함해 전달한다 (AGENTS.md 는 공통분모만)

### 3-4. 핸드오프는 어떻게 되나

바뀌지 않는다. 코덱스가 워크트리의 `outbox/` 에 남긴 HANDOFF_EVENT 파일을
오케스트레이터가 수거해 **기존 버스에 발행**한다. 검증·반려·DLQ 전부 기존 코드.
(코덱스가 봉투를 안 남기면? — 기존 3단 보정이 그대로 작동: 재요청 → 시스템 대체 발행 + 위반 기록)

### 3-5. 동시 실행 상한

`maxParallelChapters` 설정 (기본 3). 이유:
- 구독 한도를 순식간에 태우는 것을 막는다
- 실패 시 재실행 비용을 통제한다
회차가 6개여도 3개씩 두 웨이브로 나눠 돈다.

### 3-6. 완료 기준 (DoD)

- 6회차 발주 시 초고 3개가 동시에 진행되는 것이 로그로 확인된다
- 워크트리 하나를 강제로 죽여도 나머지 회차는 완성되고, 죽은 회차만 재실행된다
- 머지 후 품질 루프·연속성 점검·퇴고가 기존과 동일하게 순차 수행된다
- 끝나면 `.wt/` 와 draft 브랜치가 정리되어 있다

## 4. 사람의 자리 — 디스코드 없이 어떻게 개입하나

| 헤르메스 설계에서 | 코덱스 설계에서 |
|---|---|
| #버스-로그 채널 | `node src/cli.js bus <id>` (기존) |
| #결재 버튼 | **git diff 리뷰**: 에스컬레이션 시 오케스트레이터가 멈추고 "diff 보고 `--approve` 또는 `--revise "지시"` 로 재개하라" 안내 |
| #납품 채널 | `MANUSCRIPT.md` + 종합 보고 (기존) |
| /idea 명령 | CLI (기존) |

원격에서 보고 싶으면 작업 브랜치를 GitHub 에 푸시해 **PR 로 읽는 것**으로 충분하다.
(푸시는 기존 규칙대로 명시적 승인 필요 — deny list 유지)

## 5. 작업 순서 (ChatGPT/Codex 에게 이 순서대로)

### 1단계 발주 프롬프트 (복사용)

```
너는 Node.js 개발자다. 첨부한 소설 공장 코드의 src/llm.js 에 'codex' 프로바이더를 추가한다.
계획서 2장의 계약을 그대로 따른다. 범위 밖 리팩터링 금지.

핵심 요구:
- _dispatch() 에 case 'codex' 추가, _codex(req) 구현
- spawn 인자 배열만 사용 (셸 문자열 결합 금지)
- 읽기 전용 샌드박스로 실행, 파일 쓰기는 시키지 않는다
- 진행 로그와 최종 응답을 분리 추출 (실제 플래그는 codex exec --help 로 확인 후 결정)
- 타임아웃·재시도·예산 카운터는 기존 로직에 태운다
- config/default.json 에 providers.codex 블록 추가, doctor 에 점검 추가
- 기존 테스트 23건이 그대로 통과해야 하고, mock 프로바이더 동작이 변하면 안 된다

완료 기준: 계획서 2-4의 DoD.
```

### 2단계 발주 프롬프트 (1단계 검수 후)

```
계획서 3장(워크트리 병렬 집필)을 구현한다.
- 오케스트레이터에 초고 팬아웃 단계 추가: maxParallelChapters 만큼 워크트리 생성,
  각 워크트리에서 codex 를 쓰기 허용(워크트리 한정)으로 실행
- prompts/common.md 를 기반으로 AGENTS.md 생성기를 만들어 워크트리에 배치
- outbox/ 의 HANDOFF_EVENT 를 수거해 기존 버스로 발행
- 실패 회차 개별 재실행, 종료 시 워크트리·브랜치 정리
- 품질 루프 이후는 기존 순차 파이프라인 무변경
완료 기준: 계획서 3-6의 DoD.
```

### 검수 요령 (사람이 할 일)

1. 1단계 끝나면: `--provider mock` 으로 기존 테스트 통과 확인 → `--provider codex` 로 1회차 실전
2. 코드에서 확인할 것 3가지:
   - `spawn` 에 문자열 결합이 없는가 (셸 인젝션)
   - 코덱스에 파일 쓰기를 준 곳이 1단계에 없는가
   - API 키를 어딘가에 요구하지 않는가 (구독 인증만이어야 함)
3. 2단계 끝나면: 워크트리 하나 강제 kill 후 재실행 시나리오를 직접 돌려본다
