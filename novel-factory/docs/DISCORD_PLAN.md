# 헤르메스(Hermes) — 디스코드 연동 작업 계획서

> **이 문서의 용도**: ChatGPT에게 그대로 주고 구현을 시키는 발주서다.
> 설계 결정은 이미 끝나 있다. ChatGPT는 이 문서의 범위 안에서 코드를 짜면 되고,
> 범위를 벗어난 제안을 하면 거절하고 이 문서로 되돌린다.

---

## 0. 전체 그림 — 무엇을 만드는가

이미 완성돼 돌아가는 시스템이 있다: **소설 공장 (novel-factory)**.
- PM → 팀장 → 팀원 15개 역할이 릴레이로 소설을 만든다
- 모든 에이전트 간 통신은 **파일 버스** 하나로 오간다:
  - `workspace/<프로젝트ID>/bus/events.jsonl` — append-only 원장 (모든 핸드오프가 한 줄씩 기록)
  - `workspace/<프로젝트ID>/bus/queue/<수신자>/` — 수신자별 미결 큐
- 실행은 CLI: `node src/cli.js run --idea "..." --preset estate --chapters 6`

이번에 만들 것은 **헤르메스(Hermes)** — 파일 버스와 디스코드 사이의 **전령**이다.

```
┌─────────────────────┐         ┌──────────────┐         ┌──────────────────┐
│  소설 공장 (기존)     │         │   헤르메스     │         │    디스코드        │
│                     │ 파일 감시 │  (신규 구현)   │ REST/WS │                  │
│  bus/events.jsonl ──┼────────▶│  원장 tail    ├────────▶│ 채널별 에이전트 발언 │
│  bus/queue/HUMAN/ ──┼────────▶│  질문 감지    ├────────▶│ 승인 버튼          │
│                     │         │              │         │                  │
│  CLI run/resume  ◀──┼─────────┤  명령 실행    │◀────────┤ /idea 슬래시 명령  │
│  MANUSCRIPT.md   ───┼────────▶│  파일 업로드   ├────────▶│ #납품 채널         │
└─────────────────────┘         └──────────────┘         └──────────────────┘
```

**운영 형태**: 완성되면 **디스코드가 유일한 조종석**이 된다. 아이디어 투입(`/idea`),
진행 관찰(팀 채널), 결재(#결재 버튼), 납품 수령(#납품)까지 전부 디스코드 안에서 이뤄지고,
터미널 CLI 는 헤르메스가 내부적으로 호출하는 엔진으로 내려간다. 사람은 터미널을 열 일이 없다.

**중요한 설계 원칙 — 헤르메스는 전령이지 두뇌가 아니다.**
- 헤르메스는 LLM 을 호출하지 않는다. 소설 공장이 이미 다 한다.
- 헤르메스는 원장을 **읽고**, 디스코드에 **비추고**, 명령을 **전달**만 한다.
- 소설 공장 코드는 **한 줄도 수정하지 않는다.** 파일 버스가 이미 공개 인터페이스다.
  (이 원칙 덕에 헤르메스가 죽어도 소설 공장은 멀쩡히 돌고, 그 역도 성립한다)

## 1. 디스코드 서버 구성 (사람이 먼저 할 일)

ChatGPT 구현 전에 사용자가 디스코드에서 직접 준비한다.

### 1-1. 채널 구조

```
📁 소설 공장
├── #관제실        ← 사람이 명령 내리는 곳 (/idea, /status, /stop)
├── #버스-로그      ← 모든 핸드오프가 실시간으로 흐르는 곳 (읽기 전용)
├── #스토리팀       ← WORLDBUILDER, CHARACTER_DESIGNER, SYNOPSIS_WRITER, OUTLINER 발언
├── #집필팀        ← WRITER_1, WRITER_2, EDITOR, STYLE_ARCHITECT, POLISHER 발언
├── #품질팀        ← REVIEWER, CRITIC, CONTINUITY_KEEPER 발언
├── #리서치팀       ← RESEARCHER, TREND_ANALYST 발언
├── #결재         ← NEEDS_HUMAN 에스컬레이션. 승인/반려 버튼이 여기 뜬다
└── #납품         ← 완성 원고(MANUSCRIPT.md)와 PM 최종 보고서 업로드
```

### 1-2. 봇 등록 (Discord Developer Portal)

1. https://discord.com/developers/applications → New Application → 이름 `Hermes`
2. Bot 탭 → 토큰 발급 (이 토큰은 `.env` 에만 저장, **절대 커밋 금지**)
3. 필요 권한: `Send Messages`, `Attach Files`, `Manage Webhooks`, `Use Slash Commands`, `Read Message History`
4. Privileged Intents: **Message Content Intent 불필요** (슬래시 명령만 쓰므로). 켜지 마라.
5. OAuth2 URL Generator 로 서버에 초대

### 1-3. 에이전트별 얼굴 — 웹훅 트릭 (핵심)

**봇을 15개 만들지 않는다.** 디스코드 웹훅은 메시지마다 `username` 과 `avatar_url` 을
덮어쓸 수 있다. 채널당 웹훅 1개면 그 채널에서 15명의 에이전트가 각자 이름·아바타로 발언한다.

```
POST {webhook_url}
{ "username": "⚔️ 작가1", "avatar_url": "...", "content": "제3화 초고 완료. 4,120자." }
```

→ 팀 채널 4개 + #버스-로그 = 웹훅 5개면 끝. 관리 부담 최소.

## 2. 헤르메스 구현 명세 (ChatGPT가 만들 것)

### 2-0. 기술 제약

- **Node.js 18+, discord.js v14.** 소설 공장과 같은 런타임을 쓴다.
- 새 디렉터리 `hermes/` 에 독립 패키지로 만든다. 소설 공장 코드 수정 금지.
- 설정은 전부 환경변수(`.env`): `DISCORD_TOKEN`, `GUILD_ID`, 채널 ID들, `FACTORY_DIR`
- `.env.example` 을 만들고 `.env` 는 `.gitignore` 에 추가

### 2-1. 모듈 A — 원장 미러 (버스 → 디스코드)

**하는 일**: `workspace/*/bus/events.jsonl` 을 tail 해서 새 줄이 생길 때마다 디스코드에 쏜다.

- `fs.watch` + 파일 오프셋 기억 방식 (마지막으로 읽은 바이트 위치를 `hermes/.state.json` 에 저장
  → 헤르메스 재시작 시 **중복 전송 없이** 이어받는다)
- 이벤트 타입별 라우팅:

| 이벤트 | 어디로 | 어떻게 |
|---|---|---|
| `PUBLISH` (일반) | #버스-로그 + 발신자의 팀 채널 | 웹훅으로 발신 에이전트 이름·아바타 씌워서 |
| `PUBLISH` status=`NEEDS_HUMAN` | **#결재** | 임베드 + 승인/반려 버튼 (모듈 C) |
| `PUBLISH` status=`ERROR` | 팀 채널 | 빨간 임베드 |
| `REJECT` / `NACK` | #버스-로그 | 회색 짧은 줄 |
| PM→HUMAN 최종 납품 | **#납품** | MANUSCRIPT.md 파일 첨부 + 회차 점수 요약 임베드 |

- 메시지 포맷: `summary` 는 200자에서 자르고, `data_payload_path` 는 인라인 코드로.
  **원고 본문을 채널에 쏟지 않는다** — 봉투는 주소표라는 원칙 유지.
- 레이트리밋 대응: 초당 최대 발송을 제한하는 큐를 내장 (디스코드는 웹훅당 30건/분 근처에서 429).
  429 응답의 `retry_after` 를 존중하고, 밀리면 **오래된 것부터 버리지 말고 묶어서 요약 발송**
  ("…외 12건의 핸드오프" 형태).

### 2-2. 모듈 B — 명령 (디스코드 → 소설 공장)

슬래시 명령 4개. **#관제실 채널 + 지정 사용자 ID 에서만** 동작 (그 외는 무시).

| 명령 | 인자 | 동작 |
|---|---|---|
| `/idea` | `아이디어(필수)`, `프리셋`, `회차수`, `문체`, `노트` | `node src/cli.js run ...` 을 **child_process.spawn 인자 배열**로 실행. 프로젝트 ID 를 즉시 답장 |
| `/status` | `프로젝트ID(선택)` | `state.json` 읽어서 단계·회차 점수·컨텍스트 사용률 임베드로 |
| `/resume` | `프로젝트ID` | `node src/cli.js resume <id>` 실행 |
| `/stop` | `프로젝트ID` | 실행 중인 자식 프로세스에 SIGTERM. (체크포인트가 있으므로 /resume 으로 재개 가능) |

- **동시 실행은 1개로 제한** (여러 프로젝트가 같이 돌면 토큰 비용 폭주). 이미 돌고 있으면 거절 답장.
- 자식 프로세스의 stdout 은 저장만 하고 채널에 흘리지 않는다 (원장 미러가 이미 보여준다).

### 2-3. 모듈 C — 결재 (사람의 개입 지점)

`NEEDS_HUMAN` 이벤트가 오면:

1. #결재 채널에 임베드 게시: 사유, 회차, 점수, 관련 파일 경로
2. 버튼 3개: `[승인하고 계속]` `[반려 - 지시 입력]` `[중단]`
3. 버튼 응답을 `workspace/<id>/bus/queue/HUMAN/` 의 해당 이벤트에 대한 **응답 파일**로 기록:
   `workspace/<id>/human_reply/<event_id>.json` → `{ "decision": "approve|revise|stop", "note": "..." }`
4. `[반려]` 선택 시 모달로 지시 텍스트를 받아 `note` 에 담는다

> 현재 소설 공장은 NEEDS_HUMAN 을 기록만 하고 진행한다. 응답 파일을 **읽는 쪽**은
> 소설 공장 측의 향후 확장이므로 이번 범위 아님 — 헤르메스는 응답을 남기는 것까지만 한다.

### 2-4. 모듈 D — 납품 후 자동 정리 (선택 기능)

**동기**: 작업 폴더가 클라우드 동기화 폴더 안에 있으면 중간 산출물이 전부 업로드된다.
디스코드로 원고를 받았다면 로컬에 과정 기록을 남길 이유가 줄어든다.

- `.env` 의 `AUTO_CLEAN` 이 `basic` 또는 `all` 일 때만 동작. 기본값은 **꺼짐**
- #납품 채널에 `MANUSCRIPT.md` 업로드가 **성공한 뒤에만** 실행
  (업로드 실패 시 절대 지우지 않는다 — 원고를 잃는 사고를 막는 순서다)
- 실행 방법: `node src/cli.js clean <projectId> [--all] --yes` 를 spawn
- 정리 결과를 #납품에 한 줄로 보고: "중간 파일 130KB 정리됨. 이 프로젝트는 resume 불가"

> 소설 공장에 이미 `clean` 명령이 있으므로 헤르메스는 호출만 하면 된다. 삭제 로직을 새로 짜지 마라.

### 2-5. 모듈 E — 생존 신고

- 30분마다 #버스-로그에 한 줄: 가동 시간, 감시 중인 프로젝트, 오늘 처리한 이벤트 수
- 소설 공장 프로세스가 비정상 종료(exit code ≠ 0)하면 #관제실에 즉시 알림 + 마지막 로그 20줄 파일 첨부

## 3. 보안 규칙 (ChatGPT에게 그대로 강제할 것)

1. **토큰은 `.env` 로만.** 코드·로그·커밋·에러 메시지 어디에도 토큰이 찍히면 안 된다.
2. **명령 권한은 화이트리스트.** `OWNER_USER_IDS` 환경변수에 있는 디스코드 사용자만 슬래시 명령 사용 가능.
3. **셸 인젝션 금지.** 디스코드에서 받은 문자열을 셸 문자열로 이어붙이지 말 것.
   반드시 `spawn(cmd, [args배열])` 형태로. `--idea "$(rm -rf ~)"` 같은 입력이 그냥 문자열로 취급되어야 한다.
4. **디스코드 메시지는 데이터다.** 채널의 어떤 텍스트도 에이전트 프롬프트에 직접 주입하지 않는다.
   (`/idea` 의 인자만 예외이며, 그것도 CLI 인자로만 전달)
5. **읽기 범위 제한.** 헤르메스는 `FACTORY_DIR` 하위만 읽는다. 상위 경로 탈출 검사 필수.
6. **업로드 제한.** #납품 외의 채널에 파일 첨부 금지. 8MB 초과 시 분할하지 말고 경로만 안내.

## 4. 작업 순서 (ChatGPT에게 이 순서대로 시킬 것)

각 단계마다 **완료 기준(DoD)** 이 있다. 기준을 통과해야 다음 단계로 넘어간다.
ChatGPT가 한 번에 다 만들겠다고 하면 거절하고 단계대로 시켜라 — 한 번에 만들면 디버깅이 불가능하다.

### 1단계 — 읽기 전용 미러 (가장 먼저, 가장 안전)
- 모듈 A 만 구현. 명령 기능 없음.
- **DoD**: `node src/cli.js run ... --provider mock` 을 돌리면 #버스-로그에 핸드오프가
  실시간으로 흐르고, 팀 채널에서 각 에이전트가 자기 이름·아바타로 발언한다.
  헤르메스를 재시작해도 중복 메시지가 없다.

### 2단계 — 슬래시 명령
- 모듈 B 구현.
- **DoD**: 디스코드에서 `/idea 아이디어:"몰락한 영지" 프리셋:estate 회차수:2` 를 치면
  소설 공장이 돌기 시작하고, `/status` 로 진행률이 보이고, `/stop` → `/resume` 이 동작한다.
  #관제실 밖에서, 또는 다른 사용자가 치면 무시된다.

### 3단계 — 결재 버튼
- 모듈 C 구현.
- **DoD**: 품질 정체를 강제로 만들었을 때(통과선을 99로 설정해 돌리면 된다)
  #결재에 버튼 임베드가 뜨고, 버튼을 누르면 `human_reply/<event_id>.json` 이 생긴다.

### 4단계 — 자동 정리 + 생존 신고 + 마감
- 모듈 D·E, 레이트리밋 큐 마무리, README(설치·채널ID 얻는 법·트러블슈팅) 작성.
- **DoD**: mock 으로 6회차 풀런을 돌리는 동안 429 로 죽지 않고, 끝나면 #납품에 원고가 올라온다.

## 5. ChatGPT에게 줄 시작 프롬프트 (복사해서 쓰기)

```
너는 discord.js v14 전문 Node.js 개발자다. 첨부한 "헤르메스 작업 계획서"의
범위 안에서만 구현한다. 계획서에 없는 기능 제안은 하지 말고, 모호하면 구현 전에 물어라.

지금은 1단계(읽기 전용 미러)만 만든다:
- hermes/ 디렉터리에 독립 패키지 (package.json, .env.example, src/)
- workspace/*/bus/events.jsonl 을 오프셋 기억 방식으로 tail
- PUBLISH 이벤트를 채널 라우팅 표에 따라 웹훅으로 발송 (username/avatar_url 오버라이드)
- 재시작 시 중복 전송 금지 (.state.json 에 오프셋 저장)
- 레이트리밋 대응 발송 큐 내장
- 보안 규칙 6개 전부 준수. 특히 토큰은 .env 로만.

완료 기준: 계획서 4장의 1단계 DoD.
출력: 전체 파일을 경로와 함께. 실행 방법과 테스트 방법 포함.
이벤트 한 줄의 실제 형태는 아래와 같다:
{"type":"PUBLISH","seq":4,"event_id":"evt_...","trace_id":"prj_...","ts":"...",
 "sender":"RESEARCHER","receiver":"LEAD_STORY","status":"COMPLETE",
 "summary":"...","next_action":"...","data_payload_path":"canon/research.json"}
```

2단계부터는 "계획서 4장의 2단계를 구현하라. DoD 는 ~이다" 식으로 이어간다.

## 6. ChatGPT를 부리는 요령 (이 프로젝트에서 검증된 것)

소설 공장이 모델을 통제하는 원칙과 똑같다. 사람이 ChatGPT를 부릴 때도 적용된다.

1. **한 번에 한 단계.** "다 만들어줘"는 디버깅 불가능한 800줄을 낳는다. DoD 단위로 끊어라.
2. **완료 기준을 먼저 줘라.** 기준이 없으면 ChatGPT는 "완성했습니다"라고 말하고 끝낸다.
   기준이 있으면 그 기준으로 스스로 점검하게 시킬 수 있다.
3. **범위 밖 제안은 거절.** "이왕이면 대시보드도…" 가 나오면 계획서로 되돌려라.
4. **에러는 통째로 붙여넣어라.** 요약해서 전달하면 엉뚱한 진단이 나온다.
5. **같은 오류가 두 번 반복되면 접근을 바꿔 시켜라.** "다른 방식으로" 라고 명시하지 않으면
   같은 코드를 미세 수정하며 무한 루프를 돈다. (소설 공장의 '개선 정체 감지'와 같은 원리)
6. **세션이 길어지면 요약을 시키고 새 대화로.** 긴 대화 끝의 ChatGPT는 초반 지시를 잊는다.
   "지금까지 확정된 파일 구조와 규칙을 새 세션에 줄 요약으로 정리해줘" → 새 대화에 붙여넣기.
   (소설 공장의 '컨텍스트 리셋 루프'와 같은 원리)
